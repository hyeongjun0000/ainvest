# 1. Introduction

AInvest는 미국과 한국 주식을 대상으로 스윙 트레이딩 분석 결과를 보여주는 Streamlit 기반의 투자 보조 애플리케이션이다. 종목 티커와 매수 시드를 입력하면, 실시간에 가까운 시장 데이터를 바탕으로 현재가, 시장 상태, 스토캐스틱 지표, AI 기반 진입 및 청산 전략, 목표가와 방어선, 애널리스트 컨센서스와 리스크 스코어 등을 한 화면에서 바로 확인할 수 있다.

이 문서는 Analysis 단계 이후에 작성된 Design 문서다. app.py의 실제 코드를 기준으로 주요 클래스 구성과 객체 간의 호출 흐름, 사용자 상호작용 시퀀스, 상태 전이, 그리고 구현 요구사항을 정리했다. 다이어그램이 들어갈 자리는 나중에 시각화하기 편하도록 [그림 n] 형태로 표시해 두었다.

이 시스템은 파이썬과 Streamlit을 이용해 웹 애플리케이션으로 구현되며, 주요 설계 목표는 다음과 같다.

* 한국(KOSPI/KOSDAQ) 및 미국(NASDAQ/NYSE) 등 다중 시장 지원
* 스토캐스틱, 거래량, 이동평균, 신고가 대비 괴리율 등 기술적 분석 자동화
* LONG, SHORT, HODL, STRONG LONG, STRONG SHORT 등 전략 추천 신호 제공
* 목표가, 방어선, 예상 수익률, 리스크 스코어를 통한 투자 의사결정 보조
* 입력 즉시 분석 결과를 볼 수 있는 단일 화면 대시보드 UX 제공

# 2. Class diagram

![[그림 1] Class diagram](../images/pic3-1.png)

이 시스템은 app.py라는 하나의 파일로 구현되어 있지만, 역할에 따라 데이터 수집 계층, 분석 계층, UI 및 오케스트레이션 계층으로 나누어 볼 수 있다. 핵심 클래스는 MarketDataManager, StockAnalyzer, AInvestApp 세 가지이며, 외부 데이터 소스로는 yfinance를, UI 프레임워크로는 streamlit을 사용한다.

## 2.1 전체 클래스 관계 개요

* AInvestApp이 애플리케이션의 전체 실행을 담당한다.
* AInvestApp 내부에서 MarketDataManager와 StockAnalyzer 인스턴스를 만들어 사용한다.
* MarketDataManager는 시장 판별, 가격 이력 및 환율 조회를 맡는다.
* StockAnalyzer는 기술 지표 계산, AI 매매 레벨 계산, 신호 산출과 리스크 평가를 처리한다.
* AInvestApp.run()을 호출하면 사용자 입력부터 외부 데이터 조회, 분석 수행, 화면 렌더링까지의 전체 흐름이 제어된다.

## 2.3 클래스 설계 해설

현재 구조는 전통적인 MVC 패턴처럼 완벽하게 분리되어 있지는 않지만, 각자의 책임은 꽤 명확하게 나뉘어 있다. MarketDataManager는 데이터를 가져오고, StockAnalyzer는 계산을 하며, AInvestApp은 화면과 흐름을 제어한다. 추후 확장이 필요해지면 데이터 공급자나 분석 모듈, UI 컴포넌트를 각각 따로 추상화하고 분리하는 방식으로 리팩터링이 가능하다.

# 3. Sequence diagram

여기서는 app.py를 기준으로 사용자가 실제로 앱을 사용할 때의 흐름을 시퀀스 다이어그램 단위로 설명한다. 이 앱은 여러 화면을 오가는 구조가 아니라 단일 화면 내에서 '입력 -> 분석 -> 렌더링' 순서로 동작하므로, 각 시퀀스는 사용자 이벤트 중심으로 작성했다.

## 3.1 앱 실행 및 초기 화면 렌더링

![[그림 2] App Initialization Sequence Diagram](../images/pic3-2.png)

앱이 실행되면 AInvestApp 객체가 생성되고 run() 함수가 호출된다. 그 다음 setup_config()를 통해 페이지 설정과 레이아웃이 적용되며 기본적인 입력 영역이 화면에 뜬다. 이때는 아직 분석이 돌아가지 않은 상태다.

주요 흐름:
1. 시스템이 시작됨
2. AInvestApp.__init__()이 MarketDataManager와 StockAnalyzer를 초기화함
3. AInvestApp.run()이 호출됨
4. setup_config()에서 페이지 기본 설정과 CSS 적용
5. 헤더, 시드 입력창, 티커 입력창, 분석 버튼이 화면에 출력됨

## 3.2 종목 선택 및 시장 판별 시퀀스

![[그림 3] Ticker Detection Sequence Diagram](../images/pic3-3.png)

사용자가 티커를 치면 대문자 변환과 공백 제거 후 어느 시장인지 판별한다. .KS나 .KQ 여부에 따라 한국과 미국 시장을 가르고, 이 결과에 맞춰 이후 화면의 통화 단위나 국기 이모지가 바뀐다.

주요 흐름:
1. 사용자가 티커 입력
2. AInvestApp.run()에서 입력값을 정규화
3. MarketDataManager.detect_market()으로 시장 유형 판단
4. 화면 상단에 국가, 시장, 통화 정보가 표시됨

## 3.3 분석 실행 시퀀스

![[그림 4] Stock Analysis Sequence Diagram](../images/pic3-4.png)

'지금 분석하기' 버튼을 누르면 전체 프로세스가 돌아간다. yfinance로 데이터를 끌어오고, 여러 기간의 시계열 데이터를 바탕으로 기술 지표와 스윙 신호를 계산해낸다.

주요 흐름:
1. 분석 버튼 클릭
2. 로딩 스피너 표시
3. yfinance.Ticker() 객체 생성 및 기본 정보 조회
4. get_hist()를 이용해 일봉/주봉/월봉 데이터 수집
5. 시장 대표 지수 데이터 추가 조회 및 필요시 환율 조회
6. calc_stoch(), ai_levels() 등으로 지표와 진입가/목표가 계산
7. swing_signal(), risk_score()로 종합 신호 및 리스크 점수 계산
8. 최종 결과를 화면에 카드 형태로 렌더링

## 3.4 숏/롱 전략 분기 시퀀스

![[그림 5] Trading Strategy Branch Sequence Diagram](../images/pic3-5.png)

계산된 신호가 short 계열이면 숏 전략에 맞춰 진입가와 커버가를 계산하고, 그 외에는 롱 전략을 기준으로 텍스트와 계산식이 바뀐다.

주요 흐름:
1. swing_signal() 결과 확인
2. 숏 신호인지 판별
3. 숏일 경우 short_entry, short_cover 값을 기준으로 계산
4. 롱일 경우 buy, sell 값을 기준으로 수량과 총액, 기대 수익률 계산
5. 전략 카드와 안내 메시지 출력

## 3.5 애널리스트 컨센서스 및 리스크 평가 시퀀스

![[그림 6] Consensus and Risk Evaluation Sequence Diagram](../images/pic3-6.png)

앱에서 yfinance의 애널리스트 추천 및 목표주가 데이터를 가져와 시각화하고, 동시에 기술적인 과열도나 매도 비율 등을 바탕으로 리스크 점수를 매긴다.

주요 흐름:
1. 애널리스트 추천 데이터(recommendations) 조회
2. 최근 이력을 buy/hold/sell로 분류하고 목표가 중앙값 등을 계산
3. risk_score()를 통해 리스크 점수 산출
4. 컨센서스 막대 차트와 리스크 점수 카드 렌더링

## 3.6 예외 처리 시퀀스

![[그림 7] Exception Handling Sequence Diagram](../images/pic3-7.png)

없는 티커를 입력하거나 통신 에러가 나면 앱이 멈추지 않고 오류 카드와 함께 입력 예시를 띄워준다.

주요 흐름:
1. 데이터 조회나 계산 중 예외 발생
2. try-except 블록에서 에러 포착
3. "종목을 찾을 수 없어요" 메시지 출력
4. 미국/한국 티커 예시를 화면에 제시

# 4. State machine diagram

![[그림 8] State machine diagram](../images/pic3-8.png)

AInvest는 단일 화면 앱이지만, 사용자의 조작과 시스템의 반응에 따라 다음과 같이 상태가 변한다고 볼 수 있다.

## 4.1 상태 정의

1) Initial State: 앱이 방금 켜져서 초기화되기 전 상태
2) Ready State: 기본 UI가 뜨고 시드와 티커를 입력받을 준비가 된 상태
3) Ticker Selected State: 사용자가 티커를 치면 화면에 시장 판별 결과가 뜬 상태
4) Loading State: 분석 버튼을 누른 후 데이터를 긁어오며 로딩 중인 상태
5) Analysis Completed State: 계산이 무사히 끝나고 결과와 차트가 화면에 표시된 상태
6) Short Strategy View State: 종합 결과가 숏 전략으로 나와 그에 맞는 값들이 뜨는 상태
7) Long Strategy View State: 롱 전략 또는 관망 결과가 화면에 뜨는 상태
8) Error State: 통신 실패나 잘못된 티커 입력으로 인해 에러 메시지가 표시되는 상태

## 4.2 상태 전이 설명

시스템이 시작되면 Initial State를 거쳐 Ready State로 넘어간다. 사용자가 티커를 넣으면 Ticker Selected State가 되고, 버튼을 누르면 Loading State로 진입한다. 처리가 잘 끝나면 Analysis Completed State로 넘어가는데, 이때 결과에 따라 Short나 Long View State를 보여주게 된다. 중간에 에러가 나면 언제든 Error State로 빠지고, 다시 버튼을 누르면 Loading State로 재진입할 수 있다.

## 4.3 상태 설계 해설

이런 상태 구조는 Streamlit의 작동 방식과 잘 맞아떨어진다. 입력값이 바뀌거나 버튼이 눌릴 때마다 스크립트가 처음부터 다시 도는 구조이기 때문에, 프론트엔드의 복잡한 라우팅 없이도 입력 대기, 로딩, 결과 표시, 오류 표시 같은 논리적인 상태 유지가 가능하다.

# 5. Implementation requirements

파이썬 기반의 웹 대시보드 형태이므로 다음 환경이 필요하다.

## 5.1 Software requirements
* Python 3.10 이상 권장
* Streamlit, yfinance, pandas, numpy 패키지
* Chrome, Edge 등 최신 웹 브라우저

## 5.2 Runtime requirements
* 인터넷 연결 필수
* Yahoo Finance 서버에 접근할 수 있어야 함

## 5.3 Functional implementation requirements
* 숫자 형태의 매수 시드와 주식 티커를 입력받을 수 있어야 함
* 티커 포맷을 보고 한국장인지 미국장인지 판별해야 함
* 일봉, 주봉, 월봉 데이터를 가져와서 스토캐스틱, ATR, 이동평균 등을 계산해 내야 함
* LONG, SHORT, HODL 등의 매매 신호와 목표가, 방어선을 산출해야 함
* 실패할 경우 알기 쉬운 에러 메시지를 띄워야 함

## 5.4 Non-functional requirements
* 같은 종목을 계속 조회할 때 느려지지 않도록 캐시를 활용해야 함
* 모바일과 PC 양쪽에서 보기 편한 다크 테마 기반의 카드형 UI를 제공해야 함

# 6. Glossary

| Term | Description |
|---|---|
| Streamlit | 파이썬 코드만으로 웹 대시보드를 뚝딱 만들 수 있게 해주는 프레임워크 |
| yfinance | 야후 파이낸스에서 주가나 메타데이터를 긁어오기 위한 라이브러리 |
| Stochastic | 일정 기간 고점과 저점 사이에서 현재 가격이 어느 정도 위치에 있는지 보여주는 보조지표 |

| Swing Trading | 짧게는 며칠, 길게는 몇 주 정도 들고 가는 매매 방식 |
| LONG | 가격이 오를 것에 베팅하는 매수 관점 |
| SHORT | 가격이 내릴 것에 베팅하는 매도(인버스) 관점 |
| HODL | 섣불리 진입하지 않고 가만히 지켜보는 게 좋은 관망 상태 |
| Risk Score | 차트나 수급 등을 보고 현재 자리가 얼마나 위험한지 점수로 매긴 것 |
| Consensus | 증권사 애널리스트들의 평균적인 의견이나 목표가 |
